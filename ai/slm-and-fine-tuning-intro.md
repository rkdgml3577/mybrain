# SLM과 파인튜닝 개론 — 트랜스포머부터 RAG까지

## 핵심 개념

- **SLM (Small Language Model)** — 작은 언어 모델. LLM과 원리는 같지만 크기가 작아, 특정 도메인(버티컬)에 특화해 쓰기 좋음.
- **LLM (Large Language Model)** — 큰 언어 모델. 생성형 AI를 대표하는 용어. 학습에 많은 자원·시간이 들고 무거움.
- **예측형 AI (Predictive AI)** — 과거 데이터 패턴을 학습해 미래 결과를 예측·추천·분류하는 AI.
- **생성형 AI (Generative AI)** — 말(텍스트) 등을 생성하는 AI. 언어 모델이 대표격.
- **파인튜닝 (Fine-tuning)** — 이미 학습된 베이스 모델을 우리 목적/데이터에 맞게 추가 학습·조정하는 것.
- **트랜스포머 (Transformer)** — 현재 생성형 AI의 대표 구조. 인코더 + 디코더로 구성.
- **인코더 (Encoder)** — 입력을 "이해"하는 부분.
- **디코더 (Decoder)** — 출력을 "생성"하는 부분.
- **Attention / Self-Attention** — 문장을 순서대로가 아니라 전체를 보고, 집중할 곳을 찾는 방식. 셀프 어텐션은 한 문장 안에서 단어들 간의 관계를 따짐.
- **MLM (Masked Language Model)** — 일부를 가리고(mask) 전체 맥락으로 빈칸을 맞추는 방식. 인코더(이해) 쪽 특성.
- **CLM (Causal Language Model)** — "원인 → 결과"처럼 현재 맥락으로 다음 토큰을 예측하는 방식. 디코더(생성) 쪽 특성.
- **PEFT (Parameter-Efficient Fine-Tuning)** — 파라미터를 효율적으로 골라 튜닝하는 전략.
- **RAG (Retrieval-Augmented Generation)** — 내부 지식을 미리 저장해두고, AI가 그걸 검색·참조해 답을 생성하도록 "검색으로 강화"하는 방식.
- **임베딩 (Embedding)** — 텍스트를 컴퓨터가 이해할 수 있는 벡터(숫자, 방향)로 변환하는 것.
- **내부/외부 파이프라인** — 업무·서비스를 처리하는 흐름을 묶은 것. 내부는 사내 자원에서 직접 운영, 외부는 필요할 때 외부 LLM에 API 콜.

## 도메인·배경 지식

- **왜 개발을 배우고 AI를 배워야 하나**: AI 서비스 개발 자체를 AI에게 다 맡기면 오히려 위험하고, 결과를 검증할 사람이 필요하다. "순수 개발"로 승부하기보다 AI를 더 잘 다루는 사람이 되는 게 방향. 구글도 접근 못 하는 국내 업무 도메인 지식이 경쟁력.
- **AI의 역사**: 1950년대 컴퓨터 탄생과 함께 AI/머신러닝 필요성 대두. 2000년대 전후, 하드웨어(클러스터링/클라우드) 발전으로 사람 수준 학습이 가능해지며 딥러닝이 부상.
- **왜 "언어 모델"이 생성형 AI를 대표하나**: 인류가 쌓아온 데이터는 이미지보다 언어(텍스트) 데이터가 훨씬 많기 때문. (이미지 자체 생성은 별도의 이미지 모델을 씀)
- **왜 SLM인가 (보안)**: 상용 LLM에 사내 데이터를 연결하는 순간 영업비밀·DB·개인정보가 밖으로 나갈 위험. "프라이빗 네트워크라 안전"이라고 해도 그 정책의 결정권은 제공사에 있음. → 오픈소스 SLM 베이스 모델을 내부에 두고 파인튜닝해 쓰는 게 안전.
- **오픈소스 생태계 (HuggingFace)**: 오픈소스 AI 모델을 공유·활용하는 공간. 빅테크가 후원. 메타(Llama, 상용+오픈), 구글(Gemma, 오픈 웨이트) 등이 오픈소스에 기여하는 이유는 생태계와 시장을 키우기 위함. 상용은 돈·책임이 들지만, 오픈하면 개발자들이 자기 모델을 쓰며 시장이 열림.

## 원리·메커니즘

- **폰 노이만 구조의 한계**: 초기 컴퓨터(CPU·메모리·디스크)는 뭔가 처리하려면 데이터를 메모리에 올려야 해서, 밖(디스크)에서 읽어오면 느림. → 2000년대 전후 CPU·메모리·디스크를 옆으로 붙여 묶는 클러스터링/클라우드로 사람 수준 학습이 가능해짐 → 딥러닝.
- **딥러닝은 뇌를 흉내**: 뉴럴 네트워크. 시각 처리 흉내 = CNN(합성곱/convolution), 시간·순서 처리 = 순환형 구조.
- **왜 딥러닝만으론 말이 안 됐나**: 문장을 순서대로 쭉 받아 처리하다 보니, 앞쪽 맥락을 잊어버려 전체 맥락 이해가 약함.
- **Attention의 아이디어**: 어린아이가 문장·상황 전체를 통째로 삼킨 뒤 그 안의 관계(문법)를 본능적으로 익히는 방식(모국어 습득)을 흉내. 전체를 보고 집중할 위치를 찾음. (2017 *Attention is All You Need*, 영↔프 번역 문제에서 출발)
- **MLM vs CLM**:
  - MLM = 전체를 볼 수 있는 인코더 쪽에서, 정답을 못 보게 일부를 가려(mask) 맞추게 함 → 이해 품질↑.
  - CLM = 디코더 쪽. 현재 문장·맥락을 토대로 다음 토큰을 예측 → 생성.
- **SLM 파인튜닝은 디코더(CLM)에 한다**: SLM을 쓰는 목적은 "잘 이해"가 아니라 질의응답(말 생성). 그래서 생성 담당인 디코더(출력층)에 파인튜닝을 집중. (둘 다 쓰면 무거워짐)
- **RAG 흐름**: AI는 우리 내부 정보를 모름 → 내부 지식을 **임베딩(벡터)**해 어딘가에 저장 → 질문 시 그 저장소를 **검색(Retrieval)**해 참조 → 그 근거로 답을 생성(Generation) = 검색으로 **강화(Augmented)**된 생성. (엔터프라이즈 데이터는 수십~수백 TB라, 변환·처리 가능한 형태로 미리 만들어둬야 함)
- **예측형 AI 동작**: A→B→C로 이어지는 업무에서 각 단계의 데이터를 학습 → 미래에 A·B 데이터가 들어오면 아직 발생 안 한 C를 예측. 학습된 모델을 "모델 서빙(추론 엔진)"으로 띄워두면, 데이터가 인입될 때 자동 반응.

## 실습·도구·코드

- **HuggingFace** — 오픈소스 베이스 모델을 받아오는 곳. 사이트에서 검색해 모델 활용.
- **백엔드 스택**:
  - **Spring** — 일반 업무 로직 담당(스칼라 커리큘럼 기본).
  - **FastAPI** — AI 추론/서빙 용도로 한정해서 사용. (일반 업무 기능을 여기 다 붙이면 모듈 관리가 어려워짐)
  - **MSA** — 서비스 구성.
- **실전 진행 방식**: 선정된 SLM 모델을 로컬 PC에 다운로드 → 파인튜닝 → 실행해보고, 여러 번 시도하며 시행착오 겪기. 데모 사이트로 결과 확인(동시 접속 150명 규모).
- **오후 실습**: 3시부터 서브노트 작성(약 1시간, 템플릿 공유됨), 4시부터 주석 달린 코드를 직접 돌려보기.

## 예시

- **아이언맨의 자비스** — 사람 말을 알아듣고 처리 후 답하는 음성 비서. "AI는 결국 바깥으로 나온다"의 비유.
- **실시간 통번역(영↔프)** — 트랜스포머(인코더+디코더)가 쓰이는 대표 사례.
- **공장 예지정비** — 온도·모터 회전수 등의 패턴으로 장애를 예측 → 예방/예지 정비. (예측형 AI + 사람 판단 or 자동 처리 후 보고)
- **법령·판례 PDF 분석** — 방대하고 이미 공개된 데이터라 **외부 파이프라인(필요 시 API 콜)**이 적합한 후보. (내부에서 다 운영하기엔 부담)
- **모국어 습득** — "나는 엄마 아빠가 좋아" 문장에서 각 단어의 역할을 본능적으로 익히는 것 = 셀프 어텐션/문법 학습의 비유.

## 헷갈리는 점·질문

- 교수님이 "어렵다"고 강조한 지점들: 트랜스포머 구조, 인코더-온리 모델(BERT/ViT), PEFT. → 뒤에 교재로 다시 설명 예정이니 지금 완벽히 이해 못 해도 OK.
- MLM(인코더/이해)과 CLM(디코더/생성)의 구분 — 왜 파인튜닝을 **디코더(CLM)**에 하는지 다시 확인.
- 내부 파이프라인 vs 외부 파이프라인 — 어떤 업무를 어느 쪽에 둘지 판단 기준(보안이 필요/이미 공개됨) 정리.
- 임베딩이 정확히 어떤 과정으로 벡터가 되는지(원리)는 아직 표면적으로만 이해.
