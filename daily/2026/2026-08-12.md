# 하루 정리 — SLM 파인튜닝 (2026-08-12)

오늘은 **하나의 주제(사내용 SLM 파인튜닝)**를 개론 → 실전세팅 → 전략심화 → 손실습 4단계로 관통한 날. 아래는 4개 정리본의 "요약의 요약". (내일 서브노트의 뼈대로도 사용)

## 오늘의 큰 줄기

오늘 전체는 "보안이 중요한 조직에서, 오픈소스 SLM을 내부에 두고 우리 도메인에 맞게 튜닝해 쓰는 법" 하나로 이어진다.

1. **왜 SLM인가** — 상용 LLM에 사내 데이터를 붙이면 통제권이 벤더에 있어 유출 위험(part1·2). SLM은 외부 전송이 원천 불가능한 아키텍처를 만들어 안전 + 버티컬 도메인 깊이 확보.
2. **무엇을 튜닝하나** — 트랜스포머의 인코더(이해)/디코더(생성) 중, 우리는 "답을 생성"해야 하므로 디코더(CLM)에 파인튜닝(part1·3).
3. **어떻게 튜닝하나** — 파인튜닝은 스펙트럼(SFT/CPT/RLHF/DPO/증류). 실무 표준은 LoRA(PEFT) — 본체를 보존해 파국적 망각을 피함(part3). 이 모든 학습의 엔진은 역전파/경사하강(part3).
4. **부족한 지식은** — 자주 바뀌는 정보는 RAG(임베딩→벡터DB→검색→생성)로 보강(part4).
5. **직접 해봄** — Qwen2.5 1.5B에 LoRA 붙여 학습 파라미터 급감 확인 + FAISS/BGE-M3로 RAG 파이프라인 체험(part4).

## 핵심 개념 총정리 (중복 제거)

- **SLM / LLM** — 작은/큰 언어 모델. 우리는 "말만 하면 되고 + 내부 지식만 알면 됨" → SLM으로 충분.
- **인코더 / 디코더** — 이해 / 생성. 파인튜닝 대상 = 디코더.
- **MLM / CLM** — 마스크 씌워 양방향 이해(인코더) / 다음 토큰 순차 생성(디코더). CLM이 튜닝 대상.
- **Attention / Self-Attention** — 전체를 보고 집중할 곳을 찾음 / 문장 내 관계 파악.
- **파인튜닝 방법 스펙트럼**:
  - **SFT** (지도, 질문/정답 따라쓰기) — 이번 실습 기본.
  - **CPT** (라벨 없는 도메인 데이터 누적).
  - **RLHF** (보상 모델로 선호 학습) — "보상 모델 눈치보기" 부작용.
  - **DPO** (정답/오답 직접 제공) — RLHF 부작용 회피.
  - **지식 증류** (큰 교사 모델이 학습 데이터 생성).
- **PEFT / LoRA** — 일부 파라미터만 골라 어댑터로 학습. 본체 보존 + 저비용.
- **양자화 / QLoRA** — 가중치 정밀도를 낮춰(손실 압축) 경량화. QLoRA = 양자화 + LoRA.
- **RAG** — 임베딩→벡터DB(FAISS)→유사도 검색(Top-k)→근거 기반 생성.
- **역전파 / 경사하강** — Forward(예측)→오차→Backward(가중치 업데이트).
- **도구 스택** — Qwen2.5(한국어), `peft`/LoRA, FAISS, BGE-M3 임베딩(BAAI), Python 3.11.

## 반복·강조된 것 (시험/핵심 확률 높음)

- ⭐ **"왜 해야 하는지"가 제일 중요** — 교수님이 매 세션 반복. 코드보다 맥락·포지션 이해.
- ⭐ **SLM = 보안(내부 파이프라인) + 버티컬 도메인** — 하루 종일 반복된 최상위 논지.
- ⭐ **파인튜닝은 디코더(CLM)에** — 여러 번 강조.
- ⭐ **파인튜닝하면 성능이 떨어질 수도 있다** — 데이터가 잘 준비·명확해야 하고, 학습 내용과 실제 질문이 맞아야 성능이 오름. (내일 평가로 직접 확인)
- ⭐ **파인튜닝 vs RAG** — 안 변하는 것=파인튜닝, 자주 바뀌는 것=RAG, 분리 운영.
- **AI와 경쟁 X, AI의 주인 O** — 도메인 지식·경험이 진짜 경쟁력. 코드는 과정일 뿐.
- **협업 = 실전 점수의 50%** — 인터뷰에서 반드시 물어봄. 옆 동료 존중.

## 미해결 질문 (아직 안 풀림)

- **파인튜닝의 목적: 특화냐 보존이냐**, 그리고 어느 정도 손실까지 감수하나? → 교수님께 물을 핵심 질문. 특히 실무자로서 "이 정도 일반 성능 손실은 감수한다"는 기준선을 어떻게 잡는지. (경험 기반 답 유도)
- **rank / LoRA alpha 최적값** — "업무별로 다르다"까지만. 실데이터 없이는 감 잡기 어려움.
- **SFT vs CPT vs DPO 실무 선택 기준** — 개념은 알았으나 언제 뭘 쓰는지 판단 기준 미확정.
- **RLHF "보상 모델 눈치보기"의 구체적 발현 형태** — 실제 사례 궁금.
- **양자화 압축 한계** — 몇 bit까지 뭉개도 실사용 OK인지 (정밀도 vs 경량화).
- **청킹 전략 / Top-k / 하이브리드·리랭킹** — RAG 성능 좌우, 별도 심화 필요.
